# Archived loading screen: Steve mining an ore block

Until 08/11/2026 the landing's loading screen (`apps/web/index.html`, the three `<!-- boot:begin -->` … `<!-- boot:end -->` blocks) showed a player with the Steve skin mining an ore block with a pickaxe: the block cracked, burst and dropped a diamond. Andy asked to set it aside and replace it with the chunk-loading screen generated by `scripts/boot-screen/gen.mjs` (see `docs/features/landing-film.md`, section "Loading screen").

Nothing in the build, the tests or CI reads this folder.

| File | What it is |
| --- | --- |
| `steve-ore.py` | The generator, unchanged apart from its header. It reads the player, pickaxe, diamond and breaking textures from a local Minecraft 1.21.1 client JAR (Mojang files: see `docs/features/brand-guidelines.md`, section 12). |
| `steve-ore.boot.html` | Its exact last output, as it stood in `apps/web/index.html` at commit `fa61632`: line 1 is the `<style>` block (end of `<head>`), line 2 the `#boot` markup (just before `<div id="app"></div>`), line 3 the inline script (just before the `main.tsx` module script). |

## Restoring it

1. Either regenerate it: `python3 scripts/boot-screen/legacy/steve-ore.py <minecraft_1.21.1_client.jar>` (needs Pillow and `unzip`; it removes any existing boot blocks and writes its own three), or paste the three lines of `steve-ore.boot.html` in place of the three current blocks.
2. Put back its guards: `git show fa61632:apps/web/src/boot-screen.test.ts > apps/web/src/boot-screen.test.ts`.
3. The progress milestones reported by `HeroFilm.tsx` (`lib/boot-progress.ts`) are harmless without the chunk screen and can stay.
4. The game textures it inlines are Mojang files: brand guidelines, section 12, before any public release.
